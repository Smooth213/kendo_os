# 監査ログ・操作履歴（ゼロトラスト電子署名）

「いつ、誰が、どの端末で、何を変更したか」を秒単位で追跡・検証できるシステム監査画面です。
審判の疑義や記録ミスが発生した際、過去の全操作を確実に検証できます。
本システムは **第203条 ゼロトラスト電子署名規約** に完全準拠しており、不正なデータ改ざんを数学的に遮断・検知します。

---

## 1. 監査ログ画面の見方 {#operate-audit-view}

システム監査ログ画面（`/audit-logs`）では、Firestoreおよび端末ローカルDBから最新100件の操作イベントをリアルタイムに受信・表示します。

### 1.1 重要度に応じた3色カラーバッジ分類
各ログカードの左側アイコンは、操作の危険度・影響度に応じて色分けされています。

| アイコン色 | 対象アクション | 主な操作内容 | 想定される状況 |
| :--- | :--- | :--- | :--- |
| 🔵 **青色** (通常) | `score_added`, `match_started`, `match_finished` | 有効打突（面・小手・胴・突）の記録、試合開始・終了確定 | 通常の試合進行操作 |
| 🟠 **橙色** (注意) | `undo`, `rebuild` | 1手取り消し（スマートUndo含む）、スコアボード再構築 | 記録員の入力ミス修正やスコア再集計 |
| 🔴 **赤色** (高リスク) | `manual_update`, `force_claim` | 得点・反則の手動直接修正、コート権限の強制引き継ぎ | 審判合議による判定変更や審判端末の緊急交代 |

### 1.2 各ログの表示項目
* **アクション名**: 実行された操作（太字）
* **詳細メッセージ (`details`)**: 「赤 選手名（面）」や「第2コート 権限奪取」などの具体的な内訳
* **試合ID (`matchId`)**: 対象となった試合のユニークID
* **操作者ID (`userId`)**: 操作を実行した端末のユーザー識別子（UIDまたはPIN識別）
* **発生日時**: `MM/dd HH:mm:ss`（ミリ秒精度で記録された正確な日時）

---

## 2. 試合IDによるリアルタイム絞り込み {#filter-by-match}

画面上部の検索バーに **試合ID** を入力すると、入力と同時にリストがリアルタイムにフィルタリングされます。

* **活用例**:
  - 第3コートの準決勝で「先ほどの反則のカウントが合っているか確認したい」という場合、当該試合のIDを入力するだけで、その試合に関わる全スコア入力と取消の履歴のみが抽出されます。

---

## 3. ゼロトラスト電子署名と改ざん防止（第203条規約） {#zero-trust-architecture}

Kendo OS は「過去のデータを上書きして消す」ような従来のデータベース操作を行いません。

### 3.1 HMAC-SHA256 電子署名チェーン
すべてのスコアイベント（打突記録・反則・取消）は、発生端末の秘密鍵とスコア内容から **HMAC-SHA256 電子署名** を自動生成し、イベント自体に付与して送信されます。

### 3.2 改ざん検知・遮断（`TamperedEventException`）
悪意ある通信傍受やデータ改ざん、ローカルDBの直接編集などにより署名が一致しないイベントが検出された場合、システムは直ちに `TamperedEventException` を送出して処理を即時ブロックします。

### 3.3 クランティン（隔離退避）モード
通信障害や競合により正当性の判定が保留されたデータは、正常な試合データを破壊しないよう **クランティン（隔離退避領域）** へ安全に隔離されます。これにより、大会進行を止めることなく安全に生データを救済できます。

---

## 4. 異常ログ発見時の復旧連携 {#troubleshooting-link}

監査ログ画面のヘッダー右上にあるヘルプアイコン（❓）をタップすると、直接 **「緊急トラブル復旧ガイド（`failure_catalog.md`）」** が展開されます。
不審な赤色ログ（`force_claim` 等）や通信異常が見られた場合は、ガイドの手順に従って安全に復旧を行ってください。
