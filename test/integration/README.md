# 🥋 KendoOS Integration（結合・統合テスト）資産仕様書

## 1. 概要
本ディレクトリ（`test/integration/`）は、KendoOS における **複数ドメインサービス、CRDT同期エンジン、永続化リポジトリ、大会進行トランザクションを横断する結合・統合テスト** を格納する正式領域です。

ガバナンス第610条（`scripts/check_gov_610_test_pyramid_golden_ratio.py`）に基づき、**テストピラミッド比率 3.0% 〜 8.0% の適正範囲** として厳格に管理・保護されています。

---

## 2. 結合テストの責務と境界（Scope & Boundary）
* **対象とするテスト**:
  * 複数サービス（`MatchDomainService`, `KendoRuleEngine`, `TeamMatchCalculator` 等）の協調シナリオ。
  * オフライン耐性、CRDT 競合解決、電波切断復帰、3者同時並行同期。
  * 大会ライフサイクル完全貫通（リーグ・トーナメント・勝ち抜き戦・代表戦・不戦勝）。
  * アプリ強制終了（クラッシュ・OOM）・電源断（Blackout）からのゼロデータ損失復旧。
* **対象外とするテスト（禁止事項）**:
  * **UI操作・描画テストの混入禁止**: `WidgetTester` や `testWidgets(` を用いるUIテストは本ディレクトリに配置してはなりません（第610条セマンティック監査により自動排除されます）。UIテストは `test/widget/` または `test/e2e/` に配置してください。
  * 単一関数・単一クラスの独立した検証は `test/unit/` に配置してください。

---

## 3. 設計原則
* **超高速インメモリ実行**: UI（Flutter Engine / Skia）を立ち上げず、純粋な Dart のヘッドレス環境で動かすことで、長大な業務フロー検証でありながらミリ秒単位で高速実行されます。
* **完全決定性**: 乱数シードの固定、モック・フェイクを用いた環境独立性、タイマー仮想化を徹底します。
