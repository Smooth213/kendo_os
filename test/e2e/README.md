# 🥋 KendoOS E2E（現場UI結合テスト）資産仕様書

## 1. 概要
本ディレクトリ（`test/e2e/`）は、KendoOS における **最重要ユーザー操作フロー（WidgetTester を介した画面遷移・スワイプ・ダイアログ操作・権限変更）の完全貫通を検証するE2Eテスト** を格納する正式領域です。

ガバナンス第610条（`scripts/check_gov_610_test_pyramid_golden_ratio.py`）に基づき、**テストピラミッド比率 3.0% 以下（厳選少数・最高峰）** として厳格に管理・保護されています。

---

## 2. E2Eテストの責務と境界（Scope & Boundary）
* **対象とするテスト**:
  * 審判席・本部席の重要UIフロー（次戦追加ウィザード、タイムライン操作、公式記録PDFプレビュー＆印刷）。
  * 権限降格・セキュリティロール動的変更時のUI遮断フロー。
  * 観客Webビューア・部内戦リアルタイム追従画面フロー。
* **対象外とするテスト（禁止事項）**:
  * **UIを介さないヘッドレスシナリオの配置禁止**: `testWidgets(` を含まない純粋なロジック・サービステストは本ディレクトリに配置してはなりません（第610条セマンティック監査により自動排除されます）。UIなしの結合テストは `test/integration/` に配置してください。
  * 単一画面・単一Widgetの局所的なレイアウト検証は `test/widget/` に配置してください。

---

## 3. フレーキー対策と品質基準
* **安全待機（SafePump）の徹底**: すべての画面待機は `tester.safePumpAndSettle()` を使用し、無限ハングを水際防止します。
* **偽陽性の排除**: OSやフォント差異に左右される画像比較（PNG Golden）を行わず、論理レンダリング整合性（`tester.takeException() isNull` ＋ 要素検証）で安定性を完全担保します。
