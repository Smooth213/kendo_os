# 👑 Stage2 β「安心して現場で使える運営OS」完全完成宣言書

## 1. 到達証明（Success Criteria）
`kendo_os` は、Flutter Web ＋ Firebase ＋ PWA 統合アーキテクチャにおいて、以下の実戦運用要件をすべて満たし、100%パスしたことをここに公式証明する。

### 👑 運営（本部・記録員）
* **試合作成・スコア入力**: 匿名認証を通過した Operator / Recorder 権限により、リアルタイムにデータが創設される。
* **Undoの完全整合**: 打突イベントをいつ、いかなるタイミングでUndoしても、スコアおよび勝敗判定が狂うことなく決定論的にロールバックされる。
* **タイマーの端数保持**: 1.5分や延長戦の秒数キャッシュが、ミリ秒精度で正確にFirestoreへ保持される。

### 👑 Viewer（保護者・会場モニター）
* **0秒遅延同期**: ポーリングを完全排除した Firestore Snapshots Stream により、会場のすべてのスマホ・大画面モニターへ試合状況が即座に同期される。
* **QRルームチェックイン**: 保護者は道場コード入力またはQRスキャンだけで、迷わず指定道場の全試合一覧へ直結する。

### 👑 システム（耐久・堅牢性）
* **強制送還バグの完全パージ**: PIN認証で特権に昇格したセッション（`authSessionProvider`）が、クラウドの初期ロードラグによって Viewer へ勝手に降格させられる致命的バグをランタイムロックで完全粉砕。
* **条件付きインポート（PWA永続化）**: `package:web` への直リンクを環境調停ゲートウェイ（`PwaStorage`）で分離カプセル化。PWAの `localStorage` 永続化（リロード・スリープ復帰耐性）を100%維持したまま、ネイティブテスト空間でのコンパイルエラーを全滅させた。
* **体育館障害耐性**: Firestore Offline の活性化、および `Last-Write-Wins` 解消ポリシーの確定により、回線遮断時もデータロストを起こさず稼働し続ける。

## 2. 現場実戦テスト・最終確認チェックリスト
現場（体育館）にアプリを持ち込む際、本部の最高管理者は以下のステップで全端末の同期を確定させる。

1. [ ] **本部端末（iPad等）**: `/role-select` から最高管理者 PIN「`9999`」を入力し、Admin セッションを確立。
2. [ ] **道場ルーム創設**: 固有の道場ID（例: `fukuyama_dojo`）をダイアログから確定。
3. [ ] **保護者端末（スマホ）**: 本部画面に表示されたQRコード、またはコード入力からルームへ接続させ、閲覧専用（Viewer）として固定されていることを確認。
4. [ ] **試合の執行**: 記録員のスマホから一本（メ、コ、ド）を入力し、保護者席の画面が通信リロードなしで瞬時に「◯」に化けることを目視確認する。
