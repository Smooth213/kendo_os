# 🔒 Stage2 β 同期衝突（競合）解消ポリシー定義書

## 1. 基本方針（Last-Write-Wins）
Stage2 β版の実戦運用における複数端末間の同時データ更新、およびオフライン復帰時のデータ競合の解消ロジックは、システム複雑性を極限まで排除し現場の事故率をゼロに抑えるため、一律で以下のポリシーに固定する。

> **「Last-Write-Wins (LWW: 最終書き込み者勝利原則)」**

Firestore上の各ドキュメント（試合、スコア、タイムライン）のタイムスタンプ、またはFirebaseサーバー側が最終的に受信した時刻（ServerTimestamp）を絶対的な正本とし、最も新しいタイムスタンプを持つデータを無条件で上書き採用する。

## 2. 複雑な三者マージの禁止
現場での混乱を防ぐため、以下のロジックはβ版期間中は一律で**封印（禁止）**とする。
* **フィールド単位の細粒度マージ**: 赤のスコアと白のスコアを別々の端末から同時に部分合成する処理（データのねじれの原因となるため禁止）。
* **イベント履歴の動的再並び替え**: 通信遅延によって過去の時刻で届いた打突イベントを、タイムラインの途中に強引に割り込ませる複雑な歴史改変処理。

## 3. 剣道現場における具体的挙動
* **本部タブレットと記録員スマホの競合**: 本部側で試合の「note（備考）」を修正したタイミングと、記録員がスマホで一本を追加したタイミングが衝突した場合、1秒でも後にクラウドへ到達した側のドキュメント状態が完全な最新正本として道場空間へ全自動配信される。
* **オフライン復帰時の挙動**: 体育館の電波障害から復帰した端末が溜まっていたタスクを一斉フラッシュした際、すでにオンライン側で別の正しい試合が進行していれば、サーバー時刻の比較によって古いオフラインデータは安全に自動破棄または上書きされ、歴史の不整合を未然に防ぐ。
