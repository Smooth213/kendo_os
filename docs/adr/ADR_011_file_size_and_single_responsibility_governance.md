# ADR 011: File Size & Single Responsibility Governance (肥大化防止・単一責任原則のガバナンス化)

## Status
Accepted

## Context (背景と課題)
Kendo OS は、体育館オフライン動作、CRDT分散同期、ミリ秒単位のリアルタイム試合進行など、高度なドメイン要件を持つ。
AIを活用した高速開発サイクルにおいて、既存ファイルへの無制限なロジック追記による「ファイルの肥大化（God Class化）」や「関心の混在（UIとドメインロジックの癒着）」が起きると、以下の致命的リスクが発生する：
1. **マージコンフリクトとデグレの激増**: 巨大ファイルへの並行変更による競合破損。
2. **AIコンテキスト破綻**: 巨大ファイルに対するAIの推論精度低下とハルシネーションの誘発。
3. **テスタビリティの喪失**: モック化・分離が困難になり、テストの網羅性と実行速度が低下。

## Decision (決定事項)
Kendo OS における全コードベース（`lib/**/*.dart`）に対し、**「1ファイル500行未満・単一責任原則の厳格遵守」** を正式なアーキテクチャ憲章として制定する。

1. **ファイル行数の上限規制 (Max 500 Lines per File)**
   - `lib/` 配下のすべての実コードファイルは **500行未満** を絶対上限とする（平均目標: 150〜200行）。
   - 450行を超えた時点でリファクタリング対象（警告）とする。
2. **単一責任・純粋パーツ化原則 (Single Responsibility & Pure Decomposition)**
   - UI（Presentation）と状態管理（Provider/UseCase）、データ永続化（Repository/Service）を明確に分離する。
   - 画面・ボトムシート・ダイアログは、独立した「純粋UIパーツ」「データヘルパー」「アクションバー」に分解して構築する。
   - 親モデルや `WidgetRef` を深くバケツリレーせず、プリミティブ型や純粋コールバックを優先する。
3. **機械的強制力（3層多重ガードレール）の義務化**
   - **Layer 1 (監査スクリプト)**: `python3 scripts/check_file_lines.py` による静的行数スキャン。
   - **Layer 2 (Git Pre-commit フック)**: 500行以上のファイルを含むコミットの物理的拒否。
   - **Layer 3 (GitHub Actions CI)**: PR/Push時の自動CIビルドによるマージ拒否。

## Consequences (結果)
* **Positive**:
  - 全528ファイルが平均161行のクリーンな設計に保たれ、1,185件以上の高速自動テストが維持される。
  - AIおよび開発者がコードを修正・拡張する際、関心の分離が自明となりデグレがゼロ化する。
  - Git差分が最小化され、マルチエージェントやチーム開発での競合が根絶される。
* **Negative**:
  - 新機能追加時に「既存ファイルへの安易な追記」が禁止され、新規ファイル作成やパーツ分割の設計工数が発生する（ただし、長期的な保守コストとバグ修正工数を大幅に削減する）。
